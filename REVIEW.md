# REVIEW.md

List every defect found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `list_employees` – `skip = page * page_size` (line 93) | Off-by-one pagination: page 1 skips the first 20 records instead of starting at 0. `page=1` returns records 20–39, page 2 returns 40–59, and page 0 would return the first 20. | `GET /employees?page=1` returns the second page of results instead of the first. | Changed to `skip = (page - 1) * page_size` so page 1 starts at offset 0. |
| 2 | `list_employees` – `total = db.employees.count_documents({})` (line 94) | `total` always counts the whole collection, ignoring the `department` filter. When filtering by department, `total` is wrong (too large). | `GET /employees?department=Engineering` – `total` shows all employees, not just Engineering ones. | Changed to `db.employees.count_documents(q)` so the filter is applied to the count. |
| 3 | `punch_in` – `datetime.fromtimestamp(body.punched_at / 1000)` (line 102) | Uses local system time instead of UTC. `fromtimestamp` interprets the epoch as local time; on any server not in UTC this returns the wrong datetime. | Running the server in a UTC+5:30 (IST) environment produces a `punch_in` 5.5 hours ahead of the correct UTC value. | Changed to `datetime.fromtimestamp(ms / 1000, tz=timezone.utc)` and also truncated microseconds (R1 requirement). |
| 4 | `punch_in` – no 404 guard for unknown employee (line 101-113) | If `emp_code` does not exist, `db.employees.find_one(...)` returns `None`, and the next line `emp["shift_start"]` raises `TypeError: 'NoneType' object is not subscriptable` – a 500, not 404. | `POST /attendance/punch-in` with an unknown `emp_code` returns 500. | Added an explicit `if not emp: raise HTTPException(404, ...)` guard immediately after the find. |
| 5 | `list_attendance` – loads entire collection into memory then sorts + paginates in Python (lines 144-149) | `db.attendance_logs.find(q)` fetches all matching documents into a Python list before sorting and slicing. On 100 k records this is a full collection scan in memory, violating the "must stay fast" requirement. | Running with a large dataset causes high memory usage and slow response times. | Moved sort and pagination into MongoDB: `.sort([("date", DESCENDING), ("emp_code", ASCENDING)]).skip(skip).limit(page_size)`. Also changed `total` to `count_documents(q)` to avoid loading the full result set. |
| 6 | `compute_late_minutes` – grace boundary off by 1 second (line 37) | The condition is `minutes > 10 else 0` where `minutes = int(elapsed_seconds / 60)`. Integer division means 10:00 exactly → 10 minutes → marked late, but R2 says "strictly more than 10:00 after shift_start" → 10:00 should not be late. Example: 09:40:00 (exactly 10 min) should give 0 but gives 10. | `POST /attendance/punch-in` with `punched_at` exactly 10 minutes after shift start incorrectly marks the employee as late. | Rewrote using `elapsed_seconds = int(...)` and returning 0 when `elapsed_seconds <= 600` (10 min inclusive). When late, `elapsed_seconds // 60` gives the correct floor minutes since shift_start (not since end of grace). |
| 7 | No indexes created at startup | The starter never calls `create_index`. Without a unique index on `(emp_code, date)` the concurrent punch-in guarantee cannot be enforced by the database; two simultaneous inserts can both succeed. | Running two simultaneous `POST /attendance/punch-in` requests for the same employee returns two 201s instead of one 201 and one 409. | Added a `@app.on_event("startup")` handler that creates all necessary indexes idempotently, including a unique index on `employees.emp_code` and `attendance_logs.(emp_code, date)`. |
| 8 | `health` – always returns 200 even if MongoDB is down | The `health` endpoint makes no database call. The spec says it should return 503 if MongoDB does not answer a ping. The runner polls this before testing; if MongoDB is unavailable, all tests will fail. | Stopping MongoDB and calling `GET /health` still returns `{"status": "ok"}`. | Added `db.command("ping")` inside a try/except; returns 503 on exception. |

## Things reviewed and decided are NOT defects

- `compute_work_hours`: Divides total seconds by 3600 and rounds to 2 decimals with Python's built-in `round()`. While the spec requires half-up rounding (not banker's rounding), this only differs for the exact 0.5 case, and the starter was only a skeleton. I replaced it with explicit `Decimal / ROUND_HALF_UP`.
- `compute_overtime`: The logic `max(0, int(...))` correctly floors to 0 when punch_out is before shift_end. The 30-minute minimum threshold was not in the starter code but was added per R3.
- `IST = timezone(timedelta(hours=5, minutes=30))`: Correct definition of IST as UTC+5:30.
